# 地网 Performance SDK 开发总结

## 我要做什么

开发浏览器性能 SDK，把日志写入 AWS，经 ECS Cleaner 清洗为 Parquet，再用 Athena 和「地网」面板分析真实数据。

## 做了什么

- 完成 SDK、Ingest、SQS/DLQ、Cleaner、Firehose、S3 Parquet、Glue/Athena 全链路。
- 接入真实项目 `hono-sam-aws-learning`，Cleaner 每天北京时间 02:00 自动运行。
- 完成本地「地网」中文面板：事件、会话、错误、LCP/CLS/INP、慢页面和错误详情。
- 默认查询真实 Athena；Mock 只用于显式开发模式；浏览器不保存 AWS 凭据。

## 问题与解决

- 私有子网 NAT 失效：Cleaner 改用公网子网、临时公网 IP和零入站安全组。
- Firehose 写入 Parquet 后业务列为空：启用 JSON SerDe 大小写兼容并回归验证。
- AWS Lambda 并发额度不足：取消无法创建的预留并发，使用入口限流和账号共享并发。
- Athena 错误详情时间字段类型冲突：把 bigint 毫秒时间戳转为 UTC ISO 字符串。
- Dashboard 原来默认 Mock：改为真实 Query API 默认、Mock 显式启动。

## 验收结果

- 根测试 150/150、类型检查、构建全部通过。
- 真实 Cleaner：2 条消息全部处理，失败 0，主队列和 DLQ 均为 0。
- 新 Parquet 6,186 字节；Athena 返回 10 条事件、2 个会话。
- 地网显示真实 Hono 页面 LCP P95 约 932ms，浏览器控制台无错误。
- 浏览器产物未发现 AWS 凭据、账号、S3 路径或 Athena Query ID。

## 完成状态

学习版已完成。未完成项是公网 Dashboard、登录鉴权、SSR、WAF、告警和精确账单核对，需后续单独规划。

## 成本

已有费用包括 Lambda/API Gateway、SQS、每日一次 Fargate 与临时公网 IPv4、Firehose、S3、Glue、Athena、CloudWatch、ECR 和 Scheduler。当前使用 Parquet、日期分区、60 秒查询缓存、1 GiB 扫描上限及生命周期控制成本；实际金额需在 AWS Billing 查看。
